# 修改后审查清单与报告模板

> 本文件是**9 项审查问题的唯一出处**；`governance-review` 技能正文只定分级与边界，不复制本清单。

## 一、9 项审查问题

| # | 问题 | 合格证据的样子 |
|---|---|---|
| 1 | 是否只修复症状、未解决根因？ | 指出被违反的不变量，以及修改为何消除它而不是拦截它 |
| 2 | 是否新增了本可通过架构消除的守卫？ | 给出可替代的类型、契约、权限或事务位置 |
| 3 | 是否重复实现已有权限、校验、重试或异常处理？ | 列出重复的两处及各自责任 |
| 4 | 是否引入不必要的状态、分支、配置项或抽象？ | 说明哪条新分支/配置没有消费者 |
| 5 | 是否用 fallback、默认值或异常捕获掩盖失败？ | 指出失败路径被静默放行的位置 |
| 6 | 是否存在可安全合并、替换或删除的历史机制？ | 替代机制 + 等价性证据 |
| 7 | 是否影响接口契约、权限边界、业务不变量或故障恢复？ | 具体契约/权限/状态机位置与影响 |
| 8 | 是否有足够的测试证明修改正确？ | 测试文件与用例名；未执行的检查如实标注 |
| 9 | 是否存在只在正常路径有效、失败路径失效的约束？ | 逆序或故障注入的用例证据 |

## 二、报告模板

```md
### 审查范围
- 改动文件/模块：
- 验证证据（命令与退出码）：

### A 必须修复
- [位置] 问题 → 证据 → 建议 → 验证方式

### B 可以改进
- [位置] 问题 → 证据 → 建议

### C 暂不处理
- [位置] 问题 → 暂缓原因 → 复审条件

### 未执行的验证
- （没有则写「无」）
```

## 三、边界

- 只审查本次增量；无关历史问题放入 C 类或单独 issue，不塞进 A 类。
- 不为「显得有价值」制造建议；改动足够简单可靠时直接说明。
- 每条意见都必须能被另一个工程师复现或验证。
