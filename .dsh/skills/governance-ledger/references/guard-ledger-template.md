# 守卫台账模板

> 本文件是**条目格式的唯一出处**（字段、条目模板、生命周期判定表）；政策与落位见 `docs/agent-governance.md` §六，本文件不重复政策。

## 一、字段

| 字段 | 需要记录的内容 |
|---|---|
| ID | 唯一标识（建议 `GUARD-<模块>-<序号>`） |
| 保护目标 | 哪个不变量、资源、权限或风险 |
| 所在层 | 类型、业务层、执行层、基础设施等 |
| 触发条件 | 什么时候生效 |
| 失效影响 | 没有它可能发生什么 |
| 现有替代机制 | 是否存在其他机制承担同一责任 |
| 验证证据 | 测试、审计、运行指标（写文件与用例名，不写行号） |
| 生命周期 | 保留、合并、替换、删除或暂缓 |
| 复审条件 | 架构、依赖、权限或业务变化时何时重新检查 |

## 三、生命周期判定

| 结论 | 准入条件 |
|---|---|
| 保留 | 保证仍然有效且没有等价替代；写明证据与复审条件 |
| 合并 | 两个机制承担同一责任、失效模型不冲突；合并后仍覆盖原失效模式 |
| 替换 | 新机制提供等价或更强的保证，并有验证证据 |
| 删除 | 已证明冗余、失效或完全被替代；有调用/触发证据与回归测试 |
| 暂缓 | 证据不足或删除风险未受控；保持 fail-close 并记录待验证项 |

## 四、本仓落位建议

- 安全与业务不变量：结论写进对应 `docs/adr/` 条目，台账字段作为该 ADR 的一节。
- 测试守卫：条目写在测试文件头注释，`@req` 注解保留需求映射。
- 通用治理规则：写在 `docs/agent-governance.md` 与治理技能正文，不重复抄录 ADR 内容。
- 不新建集中式台账文件；只有守卫数量、风险与协作规模确实需要时，才考虑自动化。
