# UI 深度返工：登录背景 / 表格密度 / 行内操作 / 页面长度 / 规范自评（2026-10-20 第二轮）

> 触发：用户直接指出上一轮"100 分"的盲区——登录页背景非常丑（建议 PixiJS）、表格行高都不对、表格操作藏在下拉里不如行内、部分页面太长、UI 很多没统一；并要求**对 UI 打分、评估规范本身是否正确、评估功能设计是否有效，修复所有问题**。

## 0. 先承认上一轮的判断错误

上一轮的组件评分是**用我自己写的规范给实现打分**：基类确实统一了，但"规范本身"没有接受检验。用户指出的四点是真实的：

| 用户判断 | 上一轮实际状态（实测） | 根因 |
|---|---|---|
| 登录页背景非常丑 | 整屏高饱和亮蓝静态渐变（`from-[var(--color-gradient-start)] to-[var(--color-gradient-end)]`），无层次 | 把"品牌色铺满"当成了设计；没有背景层次/暗角/动效 |
| 表格行高都不对 | 同一表格内 48/52/56/57，跨页 48–85px；用户表"头像+两行文本"实测 72px | DESIGN 写"52px 单行/自动多行"，但 `py-4` 让**多行内容撑到 72**；规范没给"多行如何收敛" |
| 表格操作都是隐藏的 | 用户/角色/权限/应用/部门 5 个列表页全部把操作收进「⋯」下拉（组件审计：6 个隐藏菜单、0 个行内按钮） | 沿用了 shadcn 的 row-actions 惯例，没有从"操作可发现性"评估 |
| 有些页面太长了 | 权限管理 45 条一页不翻（2730px）、个人中心权限点 39 个全展开（1862px）、审计日志 20 行/页（1420px） | 列表页没有强制分页/折叠规范 |
| UI 很多没统一 | 行高、操作形态、页面长度本身就是不统一；另有状态枚举漏出 `ACTIVE`、占位假数据（个人中心"设备身份校验已启用"） | 逐页实现，没有"同形态必须同表现"的机械检查 |

**方法修正**：本轮评分脚本增加三项**用户视角**维度——行高（44–64 且同表一致）、行内操作可见性（有隐藏菜单即扣分）、页面长度（>2200px 扣分）。规范不再默认正确，先评估再修订（§3）。

## 1. 登录页：动态品牌背景（评估后不用 PixiJS）

用户建议"可以用 pixijs 优化背景"。**评估结论：不采用**，理由写进代码注释与 DESIGN：
1. 本仓依赖环境离线（registry 不可达、pnpm store 只读），无法新增依赖；
2. 纯装饰背景引入 PixiJS 意味着 +150–400KB JS + WebGL 上下文 + 生命周期管理，收益与成本不成比例；
3. 需求本质是"深色品牌底 + 缓慢极光 + 微粒"三层慢动画，Canvas 2D 足够且可控。

实现 `apps/portal/src/app/login/login-background.tsx`（零依赖）：
- 深海军蓝 → 品牌蓝纵向渐变（`#04122B → #0A2E63 → #0B3C86 → #050D1F`），替换整屏亮蓝；
- 3 团低速漂移极光（蓝/青/湖绿，`lighter` 叠加，**不用紫色**，遵守反 AI 模板规则）+ 细网格 + 64 个微粒星点 + 四周暗角；
- 性能：DPR ≤ 2、30fps 节流、`document.hidden` 暂停、卸载清理 RAF/监听；
- 可访问性：`prefers-reduced-motion` 只画静态一帧、canvas `aria-hidden`；
- 实测：桌面/390px 移动端无横向溢出、无 JS 异常、reduced-motion 下仍渲染静态背景（见 §5）。

## 2. 表格：密度、一致性与**行内操作**

### 2.1 行高（规范修订 52 → 48）

- 基类：`TableRow h-12`（48 起）、`TableHead h-10`（40）、`TableCell px-4 py-1.5`；
- 首列内容收敛到 48px：用户/应用头像 `h-8`，角色图标容器固定 `h-8 w-8`、描述单行 `line-clamp-1 leading-4`；
- 实测：用户 53、角色 49、权限 48、应用 49、审计 48（**同表内唯一值**；多行内容不再把行撑到 72）；
- DESIGN 修订：原"52px"实测在多行场景是 72px，改为"48 起 + 同表一致"。

### 2.2 行内操作（删除全部「⋯」菜单）

- 用户：详情/编辑、分配角色、禁用/恢复（3 个 32×32 图标按钮）；
- 角色：编辑、配置权限、删除（系统内置角色显示"系统内置"，**不再提供会被领域 guard 拒绝的编辑/删除按钮**）；
- 权限：编辑、删除；应用：编辑配置、注销；部门：添加子部门、查看成员、编辑、删除；
- 按钮均带 `aria-label` + `title`；危险操作用 `text-destructive`。
- 实测：组件审计中隐藏菜单 **6 → 0**，行内按钮全部可见；用户/角色/权限/应用/部门操作在真实浏览器逐个点开验证。

## 3. 规范自评与修订（DESIGN v2.3 → v2.4）

不是"实现照规范改"，而是**规范也被判错**，写进更新日志：

| 原规范 | 问题 | 修订 |
|---|---|---|
| 表格行高 52px、单元格 `px-4 py-3` | 多行内容实际 72px；同表不一致 | **48px 起（h-12）+ px-4 py-1.5 + 同表行高一致** |
| （未规定行内操作形态） | 各页沿用下拉菜单，操作不可发现 | **列表操作必须行内图标按钮，禁止收进「⋯」；每按钮 aria-label+title** |
| 登录页"渐变背景增加品牌感" | 整屏亮蓝，丑 | **深色动态品牌背景（零依赖 Canvas，含性能/降级/对比度规则）** |
| （未规定页面长度） | 权限 45 行不翻页、个人中心 39 项全展开 | **列表必须分页（≤20，权限 15/页）；超长清单默认折叠（12 + 展开全部）** |
| （允许"占位卡片"） | 个人中心"会话记录"是假占位 | **禁止占位/假数据：要么接真实数据，要么不展示** |

## 4. 功能设计评估与修复

| 设计 | 评估 | 修复 |
|---|---|---|
| 个人中心「会话记录」Tab | 只有"设备身份校验已启用/全局 SSO 节点"静态卡片，**不来自任何后端**——用户无法知道当前会话/过期时间/设备 | 接真实数据：服务端解析 JWT claims（iat/exp/jti）+ 请求头（IP/UA）+ `refresh_tokens` 活跃会话；展示当前会话（登录/过期/标识/IP/设备）+ 活跃登录会话列表 + 退出当前会话按钮 |
| 角色表对**系统内置角色**提供"编辑/删除" | 领域 guard 明确禁止修改系统角色 ⇒ 按钮点开保存必然失败，属**无效交互** | 系统角色行只显示"系统内置"，不提供编辑/删除；非系统角色提供行内三操作 |
| 权限管理一页 45 行 | 一页滚不到底，扫描/翻页成本高 | 客户端分页 15/页（3 页）+ 统一分页器；翻页保留 tab/搜索 |
| 个人中心权限清单 39 项全展开 | 页面 1862px | 默认 12 项 + 展开全部（实测 1058px） |
| 审计日志 20 行/页 | 单页 1420px | 15 行/页（实测 1160px） |
| 表格行内操作 | 至少一次点击才能看到能做什么 | 直接渲染（见 §2.2） |

## 6. 保留判断（诚实清单）

- **PixiJS 未引入**：理由见 §1；若未来要做更复杂的 WebGL 视觉（非纯装饰），再评估依赖。
- **侧边栏账户菜单仍用下拉**：那是"当前登录用户菜单"（设置/退出），不是表格行操作；下拉在此语义正确。
- **登录背景的极光参数**按当前审美调过，属于视觉偏好；性能/降级/对比度是硬约束，已量化验证。
- 未做的功能仍维持上一轮清单（菜单树形视图、强制下线 UI、登录日志 UA），本轮未改。
