# A2 修订版落地：不禁止整体替换，只禁止「不声明的整体替换」（#91）

> 日期：2026-10-14
> 来源：**#91**（retro A2 被证伪后改设计）· 关联 ADR-022 §4(b′)、CODING_STANDARDS §2
> 词汇：module / interface / seam / leverage / locality

## 一、规则（最终形态）

| 情形 | 要求 |
|---|---|
| 工厂注解为 `Partial<typeof X>` | **必须**调 `importOriginal()` 并 `...actual` spread |
| 本意就是整体替换（UI 原语 stub 等） | 把 kind 写成 **`full-replacement`** 并写明理由 |
| 其他 | 不在此规则射程 |

**为什么不是"一律禁止整体替换"**：`app-sidebar` / `command-palette` 的 `@/components/ui/*` 替身
是 `asComponentStubs<typeof X>(…)` —— 真实组件是 forwardRef，在 jsdom 里当替身用不了。
对它们加 `importOriginal` 会把真实组件**装回去**，恰好**违背 mock 本意**。

**为什么又要管**：`Partial` 只约束「键集 ⊆」、不要求完整 ⇒ 少列一个导出，它在替身里就是
`undefined`，生产代码一用到**运行时炸、`tsc` 不报**。本会话踩了 **5 次**（R6/R13/R16/R18/R33）。

## 二、落地内容

1. **枚举扩展**：`REASON_KINDS` += `full-replacement`（守卫）与 ADR-022 §4(b) 同步；
   新增 **§4(b′)** 写明工厂形态规则与"为什么不是一律禁止"。
2. **新纯函数** `findFactoryShapeViolations(source)` + `balancedBlock(source, start)`
   （**括号配平**解析，不用"扫到 `}));` 行"的启发式——后者会把相邻 mock 串成同一窗口，
   正是首版假阳性的来源）。
3. **4 个新夹具**（守卫自身被守）：夹具 11 缺 `importOriginal` ⇒ 报错并附**两种修法**；
   夹具 12 `importOriginal` ⇒ 通过；夹具 13 `full-replacement` ⇒ 通过；
   夹具 14 **不得把相邻 mock 串成同一窗口**。
4. **清扫 26 处**业务替身：`async (importOriginal)` + `const actual = await importOriginal()` + `{ ...actual, … }`；
   **3 处** UI 原语 stub 改声明 `full-replacement`。
5. **声明数字同步**：三处"X 个违例夹具 + 1 条全量扫描"（守卫 JSDoc / ADR-022 两处 / solution 文档）
   由 10 改为 14 —— 是 `docs-claims.test.ts` **变红**逼出来的（它断言文档声明的数字必须等于实测）。

## 四、过程中的两次自我踩坑（都值得记）

1. **清扫脚本把守卫文件里的夹具字符串也改写了**：`re.finditer(r"vi\.mock\(")` 命中了
   **JS 字符串字面量**里的示例 ⇒ 夹具被改坏、`no tests`（测试文件加载失败）。
   **这正是 A2 这条规则要防的形态**（"文本里的 `vi.mock(` 不是真调用"），我在实现它的脚本里又犯了一次。
   ⇒ 修复：还原守卫 + **重放**扩展脚本（夹具改用 `String.raw` 包裹，降低再次被误改的概率）。
2. **又一次英文引号导致 Python 语法错误**：在双引号字符串里写 `"不声明的整体替换"` ⇒ 脚本整段不执行。
   ⇒ 教训：写这种脚本一律用**中文引号**或三引号。

## 五、最佳实践（可复用）

1. **规则要区分"意图"，不能只看形状。** `Partial` + 无 `importOriginal` 是**形状**；
   它背后可能是"漏了导出"（缺陷）也可能是"有意整体替换"（合法）。**先测量存量**再定规则
   ——#91 的证伪过程（29 处里 3 处误伤）就是这条的代价证明。
2. **配平解析，不要行启发式。** 相邻结构的窗口会让规则"串味"；`balancedBlock` 用括号深度 +
   引号状态机，代价十几行，换来零假阳性。
3. **让声明数字有守卫。** 我改了夹具数，`docs-claims.test.ts` 立刻变红并要求同步三处文档 ——
   这类断言让"文档里的数字"不可能再漂移。
4. **改文本的脚本要先排除"文本里的示例"。** 清扫 `vi.mock(` 的脚本必须跳过注释与字符串字面量，
   否则它会去改那些**用来描述规则的示例**（本轮实际发生）。
