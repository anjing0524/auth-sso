## D1 · 管理员不得删除/禁用自己（越权自锁）→ **保留**（422）

- **依据**：契约里早就定义 `USER_ERRORS.CANNOT_DELETE_SELF` / `CANNOT_DISABLE_SELF`，而规则**从未实现**
  （#81 同类：有码无规则）。允许自删/自禁会造成"**最后一个管理员自锁死**"——**不可逆的运维事故**，
  而防护成本是两处 `if`。
- **代价**：管理员从此不能"注销自己"；需要走另一账号或 DBA 流程。**这是有意的**。
- **回滚**：删 `users/actions.ts` 两处 guard + 契约里两个码（守卫 `error-code-usage` 会立刻报"零引用"）。

## D2 · 404 统一为 `AUTH_SSO_1004` → **保留**

- **依据**：`docs/spec/API.md:44` 明文约定「资源不存在 → 404 → `AUTH_SSO_1004`」；R11 已做过同一决定；
  **实体级 not-found 码不增加信息**（资源类型已由 URL 表达：`/api/users/xxx`）。
  5 个实体级码现已从契约删除，并有**死码守卫**盯着（`error-code-usage.test.ts`）。
- **代价**：外部集成若曾按 `PERMISSION_NOT_FOUND` 之类分支，会失效。
  **仓库内已确认零消费方**（#82 的 grep 证据）；对外部需在 release note 写明。
- **回滚**：恢复 5 个码 + 5 个路由的映射（约 10 处），并把 `API.md:44` 改成"按资源类型区分"。

## D3 · 软删除后**邮箱/手机号可复用**，用户名仍不可复用 → **保留**

- **依据**：schema 的**部分唯一索引**（`ux_users_email` / `ux_users_mobile` 带 `WHERE deleted_at IS NULL`）
  **就是**"删除后释放"的设计意图；而修复前 `deleted_at` 从未被写入 ⇒ 索引**静默失效**（#86）。
  `username` 是**完整**唯一约束 ⇒ 永不复用，与"删除可恢复"一致（恢复时不会撞名）。
- **代价**：被删账号的邮箱可被别人占用（多数系统的常态）；若日后要"保留邮箱"，改索引条件即可。
- **回滚**：去掉内联查重的 `isNull(deletedAt)` 过滤（1 行）。

## D4 · #71 不加 `scopedAction` 组合器 → **维持不做**

- **依据**：组合器要消除的风险是"调用顺序被写错"，而该顺序已被**静态守卫**钉住
  （`scoped-write-guard` / `module-mock-guard` 一族）；再加一层包装只增加间接层，
  违反 Simplicity First。
- **触发条件**（不留永久决定）：出现**第 3 处**同类写路径，或出现一次"顺序被打破"的事故 ⇒ 重新评估。
- **回滚**：无需回滚（未做）。

## D5 · #89 不引入 `sonarjs/cognitive-complexity` 门禁 → **维持不引入**

- **依据**（一手 + 实证）：SonarSource 文档给出阈值 **15**（默认值≠证据）；Esposito 等
  （[arXiv:2303.07722](https://arxiv.org/abs/2303.07722)，216 名开发者）发现两者都只是
  **中等预测器**、且"**任一指标偏高时可读性反而不可预测**" ⇒ 硬门禁 ≈ **随机拦截**；
  且按本仓实测引入后大概率**零告警**（`withAuth` 估分 ~8 < 15）。
- **替代**：采纳其判据用于**人工评审**（嵌套 / 流程中断 / 嵌套中的逻辑运算符）。
- **触发条件**：出现 ≥3 层嵌套且混杂多分支的函数，或归因"难读"的事故 ⇒ 重评（先证明它会红）。
- **备注**：本环境 pnpm store 只读 ⇒ 装不上该插件；即便要引入也必须先证明它会失败（见 AGENTS.md 新增那条）。

## D6 · #91-A2 的方向：`full-replacement` 声明 → **采纳，且已落地**

- **依据**：原规则「`Partial<typeof X>` 一律必须 `importOriginal`」会**误伤 3 处 UI 原语 stub**
  （`app-sidebar` ×2 / `command-palette` ×1：真实组件是 forwardRef，无法在 jsdom 里当替身）
  ⇒ 改为**必须二选一**：`importOriginal` + spread，或声明 `full-replacement`。
- **结果**：26 处业务替身改用 `importOriginal`；3 处 UI stub 声明整体替换；守卫全量扫描 0 违规。
- **回滚**：把 `full-replacement` 从枚举移除并还原 26 处工厂（守卫会立刻变红 ⇒ 不会静默）。
