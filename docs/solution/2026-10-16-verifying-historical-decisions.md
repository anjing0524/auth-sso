## 方法（这次真正可复用的部分）

1. **只取 `file:line` 级证据**：结论后面必须跟得住"哪个文件哪一行"，否则不算核实。
2. **先定位，再断言**：本次因**猜路径**扑空 **4 次**（`src/db/schema.ts`、`src/gateway/redis.rs`、
   `apps/portal/src/lib/permissions/*.ts` 等）。正确顺序是先 `ls`/`find`/`glob` 定位，
   再 grep 断言；路径猜错时的"零命中"**极易被误读成"不存在"**。
3. **看"函数/模块现在做什么"，而不是看它是否还存在**：ADR-010 用删除线标注一期方案被取代，
   而 `validate_routing_consistency` 仍有 15 处命中——读实后不成立：它改为校验单一凭据 + 路由卫生。
   ⇒ 判断"是否被取代"看**行为**，不看**名字**。
4. **夹具要自证会红**：给 ADR-008 补守卫时，第一版正则 `[^:]+` **允许空白**，是夹具先红才发现
   （只写真值断言则漏洞静默存在）。守卫的价值全在"它真的会拦"。
5. **跨语言契约优先当证据**：`contract_tests.rs` 对着契约文件断言 cookie 名、
   `jwt-claims-fixture.json` 锁 claims 形状 ⇒ 这类地方**不需要**再补守卫；
   而 ADR-008 的权限码当时只有取值、没有校验器 ⇒ 补上。**"有没有阻断点"必须逐条核**，
   不能按"这份 ADR 看起来有测试"整体推断。
6. **正文里的示例键不能当 grep 线索**：ADR-006/007 写的 `user:{sub}:perms` 是示意，
   实际是 `REDIS_KEY_PREFIX.USER_PERMS + userId`（contracts 常量）⇒ 直接 grep `:perms` 零命中。
   以**常量名**为线索。
7. **宁可写"未核实"，不假装完整**：ADR-013 的决策 ④ 起初无法判定，就在段里标注"待核"，
   下一轮补完（per-family 级联 vs 用户级撤销的粒度辨析）——而不是含糊带过。

## 过程中的事故与恢复（值得留档）

一次工具调用在**中途被中断、结果未知**：它包含文件写入 + `git add` + `git commit` + 推送。
处置遵循"**先核实外部状态，绝不盲目重试**"：

1. 只读核实：文件**已写入**（故**不能**重跑带 `assert '## 验证' not in s` 的脚本）、
   提交**未发生**（HEAD 未变）、**未推送**（无 ahead 标记）、无 `index.lock`；
2. `git fsck` 发现 **4 个 0 字节松散对象**（中断在 `.git` 留下的半写对象，全部报 corrupt）；
3. **只删**这 4 个 0 字节文件（0 字节按定义不可能是有效对象；路径限定并先打印清单）；
4. `git read-tree HEAD` 重建索引（清掉索引 cache-tree 里指向已删对象的陈旧指针）；
5. 重新 `git add`（工作区内容完好 ⇒ blob 重建）、`git fsck` 复查干净、提交、推送。

⇒ 全程**零内容丢失**、零历史改写。教训：**中断后的第一动作是核实，不是重试**；
而"带 assert 的写脚本"在这里救了一次——若重跑，它会拒绝覆盖已正确的文件。
