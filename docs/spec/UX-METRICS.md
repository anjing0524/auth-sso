## 2. 解读与目标

| 观察 | 现状 | 规范目标 | 判断 |
|---|---|---|---|
| 页面级滚动条 | 全部路由无（登录页含 600px 高） | 0 | ✅ |
| 表格 chrome 占比（600px 高） | roles 24% / permissions 26% / audit 26% | ≤30% | ✅ |
| 表格 chrome 占比（800px 高） | roles 18% / permissions 25% / audit 20% | ≤20% | permissions 待再压（页签已并入工具条，后续可去 card 上边距） |
| 可见行（600px 高） | roles 9 / permissions 9 / audit 9 | ≥8 | ✅ |
| 可见行（800px 高） | roles 14 / permissions 12 / audit 14 | ≥14 | permissions 少 2 行（tabs+筛选在工具栏内换行导致） |
| 控件高度 | 列表 32/32；表单 36/32 | 32/36 | ✅（页签行按钮 32 合规） |
| 表头吸顶 | roles ✓（滚动 120px 位置不变） | 必须吸顶 | ✅ |
| 弹窗（600/700px 高） | 角色新建 404 / 用户新建 574 / 权限删除 228，全部在视口内 | 不得滚动 | ✅ |
| 横向溢出 390px | 全部无 | 0 | ✅ |

> **数据稀疏的页面**（users/clients 各 1 条、profile/departments 无表格）可见行天然为 1/0，
> 不代表布局问题；这类页面要用空态/引导态评估，而不是行数。演示数据可通过 seed/demo 脚本补足。

## 3. 每轮改动的对比规则

1. 改动前后各跑一次脚本，把上表复制进 PR/roadmap，标注 delta。
2. 只允许"目标达到 + 无回归"的改动合并；若目标与产品收益冲突，在规范 §9 记录理由。
3. 新页面必须先在 `UX-GUIDELINES.md` §8 矩阵登记任务与目标，再实现。

### 6.4 判定说明

- **页面级滚动/横向溢出**：1512×800、1139×600、390×844 三档全部为「无」——核心页面通过硬门槛。
- **chrome/行数**：1139×600 下列表页 chrome 均 ≤30%（users 25 / roles 24 / permissions 26 / clients 25 / audit 26）；permissions 与 audit 可见 9 行（≥8）。users/roles/clients 当前演示数据仅 1–3 行，行数不作判定，布局与空态另行验证。
- **dashboard** 不是列表页（含指标卡/动态/快捷入口），chrome 不作为预算；其首屏信息完整、无滚动。
- **弹窗**：用户创建 550（本轮从 598 压缩）、角色创建 404、权限删除 228，均 ≤600 视口且 `scrollHeight = clientHeight`。
- **已知非布局缺口（不阻塞本验收）**：建号→分配→登录 e2e 尚未固化；审计 `USER_CREATE` 未记录 targetUserId（写入侧）；角色按权限数排序未做。
