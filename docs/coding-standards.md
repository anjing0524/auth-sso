# CODING_STANDARDS

**谁读这个文件**：评审代理（`/code-review` 的 Standards 轴）。实现代理不读——它每轮的上下文已经很紧，规范该由评审在拿到 diff 时施加。

**这里只收判断题**：机器能判的一律**造确定性检查**（ESLint 规则、守卫测试、pre-commit 钩子、CI 步骤），不要写成散文。判断一条规则属于哪边的测试：*能不能写出一个只需要 diff 就能判定的机械模式？* 能，就去造检查；不能，才留在这里。

本仓的规则本体在 `docs/adr/ADR-022-test-authenticity-strategy.md`，可执行副本是 `apps/portal/__tests__/api/module-mock-guard.test.ts`。本文件收的是这两处**表达不了**的判断题——测试与证据的**成色**。

---

## 1. 变异必须留下**控制证据**

改坏生产代码后，失败的**原因**必须与预期一致：不是"变红了就算数"。

- **反例（本仓真实发生过）**：把校验写成 `(async () => {}) && db.insert(...)` 去做"不落库"变异——`&&` 右侧仍会求值，等于没变异，15 例全绿被误读成"这套测试没有覆盖"。
- **要求**：证据含 ①变异的 diff ②命令 ③输出，且输出的失败**消息**能对上你预期破坏的那条语义；做不到就说明这个点位**不可变异**，那本身是结论（记进票据）。

## 2. 理由里的行为断言必须与代码实际形态相符

注解（如 `// @allow-module-mock <target> <kind>: <理由>`）是给人读的契约，**写下的行为断言必须真**。

- **反例**：工厂整体替换模块（无 `importOriginal`）时，未列出的导出是 `undefined`；注解却写"哈希走真实实现"。同类漏修曾在 9 个文件里只改了 4 个。
- **要求**：写完理由，回头看一眼工厂**实际**返回了什么；`importOriginal` + spread 才配得上"其余走真身"。

## 3. 数字必须来自粘贴的命令输出

票据、提交信息、ADR 里的每个计数（点位、文件数、夹具数、净删行数）都要有一段**可复制的命令 + 原始输出**。手抄的数字会漂移——一个会话内漂移过 4 次（迁移前 53 实测 50、夹具数 7→9→10、文件数 11→10、用例归因 -18）。

## 4. 恒真断言不算证据

一条断言如果**换个实现也照样通过**，它就不是证据。

- 三个真实形态：从未被播种的状态（`isJtiRevoked('从未写入的 jti') === false`）；由 mock 喂出来的值（`revokedJtiCount` 来自 `mockResolvedValue(3)`）；空数组配 `toBeDefined()`。
- **要求**：断言要让"有东西可丢却没丢"变得可观测——先播种、再操作、再断言状态**发生了变化**（或**未被**变化）。

## 5. 类型化工厂的键集契约只对**对象字面量**成立

`Partial<typeof xModule>` 的键集约束靠多余属性检查，而它**不适用于函数调用结果**。把工厂的返回值写成"调用一个 helper"时，约束必须前移到那个 helper 的**返回类型**，否则幽灵键静默通过（本仓实测：给 `makeSidebarMock()` 的返回值加幽灵键，零诊断）。

## 6. 被 `vi.mock` 工厂引用的 helper 必须是**函数声明**

`vi.mock` 的工厂会被提升到文件顶部；`const` 箭头函数在工厂执行时仍在 TDZ，结果是**整个测试文件加载失败**（本仓发生过两次）。

## 7. 声称"由工具强制"的，必须指出工具在哪一步跑

- **反例**：CI 作业名叫 `Full CI (Lint + Test + Coverage)`，而覆盖率既没有阈值、也没有任何步骤真的产出覆盖率——名字是唯一的那句"声称"。
- **要求**：写"必须/强制/门禁"时，同时写出**阻断点**（哪条命令、在哪个 job/钩子里）；写不出来的，就改成"约定"，别写成"强制"。

## 8. 替身不得手写被替换者的行为

`vi.mock` 的替身要么**用真身**，要么**复用生产的判定/映射函数**；不要手写一份"等价实现"。

- **反例（#87）**：某测试文件的 `withPermission` 是**手写复刻**——领域错误映射为响应、其余异常照常抛出，注释还写着"其余异常照常抛出（审计失败用例依赖这一点）"。**那句话就是缺陷的收据**：生产里 `withPermission` catch 一切并 `mapServerError`，而手写的状态码表已与 `ERROR_STATUS` 漂移（按 code 映射 vs 按类名映射）。
- **要求**：写下"与生产一致"之前，先看被替换者**实际**做了什么；能复用就复用（`mapServerError` 这类纯函数直接调）。`auth-bypass` 的边界只划在**输入**上（谁已登录/已授权），不要连错误映射一起替换。

## 9. 红必须红在**正确原因**上

变异/测试失败的红，必须能对上你**预期破坏**的那条语义；红在夹具或环境上不算数。

- **反例（本会话三次）**：夹具形状写错（对象当数组传 ⇒ 整段种子被静默跳过，用例"通过了重复创建"）；根部门被重复播种（撞唯一键）；变异后**自己删掉了夹具行**——三种红都不是被测语义的红。
- **要求**：看到红先读**失败消息**，确认它指向预期语义；不是就修夹具/环境，再重跑。**假绿比失败危险，假红比假绿更浪费时间。**

## 10. 文档里的"未来时承诺"必须带触发条件

写"以后再…/待评估/另立 effort"时，必须同时写**什么条件下重新评估**；写"必须/强制/门禁"时按 §7 给出**阻断点**。

- **反例**：ADR-022 的"Rust 侧另立 effort"与 ADR-019 的两处"待评估项"长期无人认领（本仓实测：挂了数月）；ADR-002 声称的"根部门不可删除"守卫当时**并不存在**。
- **要求**：未来时承诺 = 一句话写清「触发条件 + 届时怎么验收」。否则它会在文档里沉淀成没人读的层（writing-for-agents 称之为 sediment）。

## 11. 同一事实只写一处；写第二处就必须有断言维系

**"声明范围 ≠ 实现范围"**是本仓反复出现的一类缺陷（2026-10-15 一个会话内 **3 次**）：
守卫文件头列了 `; true` 禁令而正则表没有；ADR 说"**15** 个违例夹具"而紧随的枚举仍列 **10** 项；
README 声称"生成时脚本断言无重复"而**根本不存在**这样的脚本。

- **要求**：同一事实（清单 / 枚举 / 计数 / 豁免集）只保留**一处来源**。若必须写第二处
  （例如给人读的 JSDoc），要么**指向第一处**（"规范性清单见下表"），要么加**断言**把两者绑住。
- **数字分两类，待遇不同**：
  - **验证类数字**（"当时 104 文件 865 用例全绿"）= **时点记录**，允许，且应当带日期或上下文；
  - **规范性声明的数字**（索引篇数、夹具数、禁令条数、豁免集）= 必须由断言维系
    （本仓已有：`docs-claims` 管夹具数、`docs-references` 管索引篇数与唯一链接、
    `module-mock-guard` 管豁免集相等、`gate-inventory-guard` 管禁令表、`docs-api-error-codes` 管错误组完整性）。
- **反例的可执行判据**：当你写下"必须/全部/每一个"时，问一句 **"如果我少写一条，谁会红？"**
  —— 答不上来，就说明这句话只是**愿望**，不是约束。
